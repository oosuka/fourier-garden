# 数学層と音楽スコアの視覚連動強化

> **状態:** 実装済みの設計記録。音響と反復スコアの現在の制約は、後続の
> [`2026-06-13-mathematical-integrity-hardening-design.md`](2026-06-13-mathematical-integrity-hardening-design.md)
> を正とする。

## 目的

`Residue Bloom` の左側エピサイクルと右側主履歴波形について、音楽との連動を
初見でも認識できる強さへ高める。

既存の背景、膜、粒子、ハロー、ブルームによるスコア応答は維持する。
追加表現は厳密な数学層へ重ねる詩的造形層として実装し、有限フーリエ級数の
座標、半径、位相、投影、観察時間を変更しない。

## 不変条件

次の値と処理は変更しない。

- 有限フーリエ級数
  \(f(x)=5\sum_{k=0}^{12}(k+1)^{-1}\sin((4k+1)x)\)
- 調波番号 \(n_k=4k+1\)
- 正弦振幅 \(A_k=5/(k+1)\)
- 正弦位相0
- フェーザ終点 \(z(x)\)
- 主波形 \(f(x)=\operatorname{Im}z(x)\)
- 観察時間 \(x(t)=0.31t\)
- エピサイクルの円半径、中心、スポーク、終点、接続線
- 主波形の座標と投影倍率
- 音響の基礎知覚重み \(A_k/(k+1)^{1.4}\)
- 左右デチューン後のナイキストガード
  \(\max(n_k\nu_j(1-d),n_k\nu_j(1+d))<0.45F_s\)

共有スコア応答から、数学層の座標、半径、線幅、カメラ、観察時間を変更する値を
生成してはならない。

## 選択した表現

採用案は `B / 調波コロナ + 履歴パルス` とする。

### 左側: 調波コロナ

13個の厳密な円とは別に、同じ中心と半径を持つ発光円を13個生成する。
これを調波コロナと呼ぶ。

各コロナは、対応する調波の基礎知覚重み

\[
w_k=\frac{A_k}{(k+1)^{1.4}}
\]

を最大値で正規化した値と、共有スコアの発音インパクト、余韻、フレーズ色から
透明度と色を決定する。

コロナは円の位置と半径を厳密なエピサイクルから毎フレーム受け取るが、
数学円のマテリアル、線幅、座標は変更しない。発音中は低次調波を主として
13個の円へ光が受け渡されるように見せる。高次調波も消さず、重みに応じた弱い
発光として残す。

スポークの始点と13個の終点へ、計14個の小さな発光ノードを重ねる。
ノードも厳密なスポーク座標を読み取るだけで、接続ベクトルを移動しない。

### 右側: 履歴パルス

主履歴波形とは別に、同じ有限フーリエ級数と同じ観察時間・投影倍率で計算した
短い発光線を重ねる。これを履歴パルスと呼ぶ。

現在時刻の発音は接続線側から主波形へ入り、その後は波形の履歴方向へ流れる。
パルスの点は主波形と同じ
`projectSeriesToVerticalAxis()` の結果を使用する。パルス専用のノイズ、
振幅変形、位相ずらし、縦方向オフセットを加えない。

パルスの形状は正確な主波形の部分集合であり、次の値だけを詩的に変化させる。

- 表示する履歴区間の長さ
- 透明度
- 色
- 発光点の大きさ

表示区間は共有スコアの直近イベントから決定する。最大4イベントまでを
決定的に再構成し、可変な生成状態は持たない。144秒境界では、前周回の履歴を
そのイベントが実際に発生した絶対時刻から再評価して連続させる。

## 色と強度

既存のフレーズ色を維持する。

- フレーズ番号0: 暖色の金。4音句の先頭として最も強い
- フレーズ番号1: シアン
- フレーズ番号2: バイオレット
- フレーズ番号3: シアンと金の中間

イントロ冒頭3秒では4つの発音について、調波コロナと履歴パルスの両方が
認識できなければならない。フレーズ番号0は後続音より少なくとも10%強くする。

強度は背景応答より局所的に明確にするが、数式、数学円、主波形の白い中心線を
覆わない。WebGPUのブルームがなくても、強制WebGL2で透明度と色によりイベントを
識別できる状態にする。

## データフロー

1. `src/audio/musicalScore.ts` が48小節イベント表を一度だけ構築する。
2. `CanvasStage` がtransport時刻を1回取得し、共有スコアを1回評価する。
3. `getResidueBloomVisualResponse()` が発音インパクト、余韻、フレーズ色、
   調波コロナ強度、履歴パルス強度を有界値として返す。
4. シーンは厳密なエピサイクルと主波形を従来どおり更新する。
5. その後、同じ正確な座標を参照してコロナと履歴パルスだけを更新する。

この視覚連動の実装時点ではAudioWorklet、音響式、共有イベント表の構成を
変更しなかった。後続の数学的整合性是正では、反復イベント表から評価済み
フェーザ値を除外し、絶対イベント時刻で評価する契約へ更新している。

## 実装境界

主な変更対象は次のとおりとする。

- `src/patterns/residueBloomVisualResponse.ts`
- `src/patterns/residueBloomVisualResponse.test.ts`
- `src/patterns/residueBloomScene.ts`
- `docs/mathematical-model.md`
- `README.md`
- `design-qa.md`

数学の純粋関数と音響実装は変更しない。追加表現のために
`src/math/fourier.ts` または `src/audio/` の定義変更が必要になった場合は、
実装を止めて影響範囲を再検討する。

## リソースと性能

- コロナ13本と発光ノードはシーン初期化時に一度だけ生成する。
- 履歴パルスは固定数の動的バッファを再利用する。
- 毎フレームのThree.jsオブジェクト、ジオメトリ、マテリアル、配列生成を行わない。
- 品質低下時も厳密な数学線を削減せず、必要ならパルス本数・余韻長を先に減らす。
- `dispose()`で追加ジオメトリとマテリアルを既存シーンの走査から破棄する。

## TDDと受け入れ条件

実装前に、次の失敗テストを追加する。

- 13調波のコロナ重みが
  \(A_k/(k+1)^{1.4}\) の正規化値と一致する。
- 低次調波のコロナが高次調波より強い。
- phrase index 0のコロナ・パルスが後続音より少なくとも10%強い。
- コロナとパルスの全制御値が144秒全域で有限かつ有界である。
- visual responseがendpoint、epicycle scale、wave scale、camera offset、
  phase offsetを公開しない。
- 履歴パルスの縦座標が同時刻の
  `projectSeriesToVerticalAxis()` と一致する。
- 144秒前後でパルス履歴が不正な位置へ飛ばない。

集中テスト成功後に、次を確認する。

- 数学テストが無変更で成功する。
- `npm run check` が成功する。
- `git diff --check` が成功する。
- WebGPUとforced WebGL2で最初の3秒、bloom、hushを確認する。
- 左のコロナと右の履歴パルスが発音ごとに認識できる。
- 白い数学線の座標、円半径、終点、接続線、主波形が発音で跳ねない。
- 3840 x 2160で性能目標を再確認する。

## 非目標

- 数学円の半径や位置を音でpulseさせない。
- スポーク、終点、接続線、主波形を音で変形しない。
- 主波形へ装飾ノイズ、テーパー、位相ずらしを混ぜない。
- 音響、48小節構成、キャリア、係数、知覚重みを変更しない。
- 新しい依存、モバイル対応、章、編集UIを追加しない。
